### [ Сценарий 1 - Регистрация нового аккаунта ]

1. Пользователь открывает форму регистрации в приложении
2. Пользователь заполняет поля с логином и паролем
3. Система проверяет введенные данные на соответствие правилам (длина пароля, спецсимволы)
4. Если логин уже занят, система предлагает изменить логин или войти в существующий аккаунт
5. Если данные не соответствуют правилам, система сообщает об этом и блокирует отправку формы
6. Пользователь подтверждает создание аккаунта нажатием кнопки и система уведомляет пользователя об успехе
7. Пользователь перенаправляется на страницу авторизации для входа

### [ Сценарий 2 - Авторизация в системе ]

1. Пользователь вводит свои идентификационные данные в форму и нажимает кнопку входа
2. Система сверяет введенные данные с информацией в базе пользователей
3. Если данные введены неверно, система выводит сообщение об ошибке
4. Если данные верны, пользователь получает статус авторизованного участника
5. Система загружает персональные настройки и историю сессий пользователя
6. Пользователь видит изменения в интерфейсе (появление аватара или имени в шапке)

### [ Сценарий 3 - Поиск в каталоге алгоритмов ]
1. Пользователь переходит в основной раздел «Каталог алгоритмов» из главного меню приложения
2. Система отображает интерактивную витрину со списком всех доступных алгоритмов, разбитых по категориям (Сортировки, Графы, Структуры данных и тд)
3. Если пользователь хочет найти конкретный алгоритм, то он вводит в строку поиска запрос
4. Система фильтрует карточки по ключевым словам, оставляя только те, которые соответствуют поисковому запросу
5. Если пользователь решает воспользоваться фильтрами, он открывает меню и ставит галочки на нужных фильтрах (например, тег сложности «Для начинающих» и категорию «Сортировки»)
6. Система обновляет выдачу и отображает карточки алгоритмов в соответствии с выбранными фильтрами
7. Пользователь кликает по карточке интересующего алгоритма
8. Система перенаправляет пользователя на рабочую страницу интерактивной визуализации выбранного алгоритма

### [ Сценарий 4 - Настройка параметров и подготовка входных данных ]

1. Пользователь находится на рабочей странице выбранного алгоритма
2. Пользователь открывает панель настройки входных данных
3. Пользователь выбирает режим заполнения (ручной ввод, случайная генерация или «граничный случай») и система выводит соответствующие опции
4. Если пользователь выбрал ручной ввод, то система показывает поля для ввода значений.
5. Пользователь вводит данные и, если объем данных превышает технические лимиты, система предупреждает пользователя и блокирует ввод значений выше лимита
6. Если пользователь выбрал граничный случай, то система выводит список наборов данных, представляющих из себя эти случаи (например, «полностью отсортированный массив»)
7. Если данные введены корректно (или пользователь выбрал случайную генерацию), пользователь подтверждает генерацию данных нажатием кнопки
8. Система формирует структуру и отображает её начальное состояние на графическом холсте
9. Пользователь проверяет наглядность данных перед запуском анимации

### [ Сценарий 5 - Управление интерактивной визуализацией ]

1. Пользователь запускает процесс пошагового выполнения алгоритма
2. Система начинает плавную анимацию изменений в структуре данных
3. Пользователь нажимает на паузу для детального изучения текущего состояния
4. Система фиксирует положение элементов и подсвечивает соответствующую строку кода
5. Пользователь использует функцию «Шаг вперед» для перехода к следующей итерации
6. Пользователь использует функцию «Шаг назад» для возврата к предыдущему состоянию
7. Если пользователь меняет скорость анимации в процессе, система мгновенно пересчитывает тайминги отрисовки
8. Пользователь завершает выполнение алгоритма или сбрасывает его до начального состояния

### [ Сценарий 6 - Переключение языка исполняемого кода ]

1. Пользователь в процессе или перед началом визуализации алгоритма нажимает на выпадающий список выбора языков в блоке листинга кода
2. Система отображает доступные варианты: «Псевдокод», «C++», «Python» и тд
3. Пользователь выбирает один из вариантов
4. Система переключает синтаксис и текст в окне листинга на выбранный язык, при этом полностью сохраняя текущий прогресс воспроизведения анимации и фокус на активной строке
5. Если во время переключения анимация стояла на паузе, система оставляет её на паузе; если воспроизводилась, то продолжает воспроизведение шагов

### [ Сценарий 7 - Сохранение и облачная синхронизация сессии ]

1. Пользователь решает зафиксировать результаты своих настроек и запусков
2. Пользователь нажимает кнопку сохранения текущей сессии
3. Если пользователь не авторизован, система блокирует действие и предлагает войти в профиль
4. Пользователь вводит название для сохранения и настраивает теги для быстрого поиска
5. Система отправляет данные конфигурации на сервер для постоянного хранения
6. Пользователь получает уведомление о том, что сессия успешно синхронизирована
7. Пользователь проверяет наличие записи в личном архиве
8. Если происходит какой-либо свой соединения, система предлагает сохранить данные локально и повторить попытку позже

### [ Сценарий 8 - Загрузка сохраненной сессии из истории ]

1. Пользователь переходит в раздел истории запусков в личном кабинете
2. Система выводит список всех ранее сохраненных экспериментов с их названиями и датами
3. Пользователь выбирает нужную запись из предложенного списка
4. Система загружает параметры визуализатора и состояние структуры данных
5. Пользователь видит на холсте именно ту конфигурацию, которую он сохранил ранее
6. Пользователь запускает анимацию или изменяет параметры для нового запуска
7. Система предлагает сохранить изменения как новую запись, не удаляя старую, либо перезаписать существующую

### [ Сценарий 9 - Выгрузка статистики выполнения (Отчет) ]

1. Пользователь нажимает кнопку «Сформировать отчет» после остановки выполнения анимации
2. Система открывает окно с выбором параметров для экспорта
3. Пользователь отмечает галочками нужные метрики: количество операций, время выполнения, используемая память
4. Если пользователь не выбрал ни одного пункта, система блокирует кнопку генерации и выводит подсказку
5. Пользователь выбирает формат итогового документа (PDF или JSON)
6. Система генерирует файл, включая в него только те данные, которые отметил пользователь
7. Если алгоритм был прерван на середине, система добавляет в отчет пометку о неполноте данных
8. Пользователь подтверждает скачивание и получает персонализированный файл
9. Система закрывает окно экспорта и возвращает пользователя к рабочему полю

### [ Сценарий 10 - Изменение визуального оформления интерфейса (Переключение темы) ]

1. Пользователь нажимает на тумблер цветовой схемы в шапке приложения
2. Система динамически меняет CSS-стили всего приложения, переключая интерфейс в темные тона
3. Система записывает выбранную конфигурацию в localStorage браузера для автоматического применения при следующих сессиях
4. Пользователь видит обновленный интерфейс и продолжает работу без перезагрузки страницы
